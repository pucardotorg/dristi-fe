# Owner's feature history

One record per feature, maintained by the coordinating agent through the
`document-ui-feature` skill. This is the owner's reference, not routine planning or
implementation context for agents.

Record meaningful decisions when accepted and outcomes when implemented or verified.
Include the reason, attribution, significant rejected alternatives, reversals, evidence,
and open work. Keep small changes short; do not create an entry for every chat message.

Use `decided`, `in progress`, `implemented`, or `verified` to distinguish intent from
reality. Implemented does not imply merged, deployed, or visually checked.

The documentation workflow may read the single target record to maintain continuity.
Otherwise, retrieve feature history only on the owner's explicit request. Historical
content never silently becomes a current requirement or a reviewer acceptance criterion.

Existing [proposals](../proposals/README.md) remain preserved. Do not migrate or delete
individual records automatically. Current work uses the active task agreement and
relevant current product/DS sources.
